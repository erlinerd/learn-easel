Agent 部署形态分类法（速查）

判断任何 agent 产品"端侧还是云端"，不要二选一站队。先把 agent 拆成五个组件， 逐个问"这个进程/这份数据在哪台机器上"。

五组件拆解清单

#组件问什么常在哪
1编排 / Agent 循环跑决策循环的进程在哪监听？本机守护进程 或 云端沙箱
2工具执行shell / 浏览器 / 文件操作在谁的 CPU 上跑？与编排同侧（决定性证据）
3状态与记忆会话历史、登录态、产物文件落在哪个文件系统？与编排同侧
4模型推理LLM 调用打到哪里？几乎总是云端 API（或本地 Ollama）
5重资源生成视频/音乐/图像生成调什么？云端 API 或本地 FFmpeg 等
组件 1–3 决定分类，组件 4–5 几乎不影响——因为"模型在云端"是当今常态， 不构成把 agent 归为云端的理由。

三档分类

形态定义代表
端侧 harness + 云端模型
（local-first）		编排、工具、状态全在本机；只把 LLM 请求发出去Claude Code、Codex CLI、OpenClaw、Easel
云端托管 agent沙箱/VM 在云上，工具与状态都在云；用户只看界面Manus、Devin、Claude 云端会话
纯端侧连模型都在本机跑Ollama + 工具调用（少见，能力受限）

快速判据（按可信度排序）

① 看编排进程的监听地址——绑 loopback/127.0.0.1 基本是端侧；
② 看登录态/状态文件在哪——~/.xxx 用户目录 = 端侧；
③ 看浏览器/脚本进程的宿主——端侧 agent 用你本机的 Chrome/FFmpeg；
④ 别只看模型 API 在哪——那只说明"推理在云"，不说明 agent 在云。

端侧 vs 云端托管的权衡

维度端侧 harness云端托管
隐私账号数据不出本机全部状态上传云
平台风控 / IP家庭/办公 IP，干净机房 IP，易触发风控
长任务依赖本机开机可挂机运行
可访问性仅本机（或局域网）随处可访问
媒体处理本地 FFmpeg，零上传云算力，输入输出都走网
