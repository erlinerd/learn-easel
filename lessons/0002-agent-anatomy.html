Agent 的解剖学：六件套构造蓝图

45 min · 前置课的 23 个概念在这里合成一张图，然后拿去解剖 Easel

🎒 预备知识：完成前置课全部 24 课（入口：第 0 课）

本课唯一结论：任何 LLM agent = 六件套—— ① Harness（循环）② 提示词栈 ③ 能力系统 ④ LLM-脚本分工 ⑤ 记忆与状态 ⑥ 安全边界。 前置课你学的每个概念都有一个家：这张表就是地图。

一、基础：为什么需要一张"构造蓝图"

前置课你学了一堆零件：loop（A3）、技能（A2）、记忆（A6）、闸门（A12/A13）…… 但零件清单 ≠ 整机图纸。看一个真实 agent 仓库（几万行代码、几十个目录）时， 新手的问题是没有坐标系：每个文件都认识，拼起来不知道是什么。 六件套就是坐标系：任何 agent 无论多复杂，都由这六个构造块组成， 每个文件、每个目录最终都能挂到某一件上。挂不上的，要么是废话要么是宝藏—— 两种都值得你停下来看一眼。

二、六件套 × 前置课概念的家谱图

#构造块一句话职责前置课里学过的零件Easel 的实现
1Harness（运行时） 模型外的运行时容器 loop/三条铁律（A3）、并发隔离（A9）、harness 选型（A17） 借 OpenClaw gateway（loopback:18789）
2提示词栈 每一轮让模型看到什么 上下文工程四原则（A5）、消息协议（L4）、注意力衰减 SOUL→AGENTS→CONTEXT→SKILL 四层 + 画像内联（L05 详讲）
3能力系统 能力怎么声明/路由/加载 Tool/MCP/Skill 三代（A2）、渐进披露（A5） 114 个技能目录，frontmatter 路由
4LLM-脚本分工 决策归模型，确定性 IO 归代码 幻觉与软失败（L5/A13）、精确计数代码化（L2） "prompt 薄壳 + 确定性厚脚本"：48 个共享脚本
5记忆与状态 会话持久化 + 长期记忆作用域 四种记忆形态（A6）、compaction（L2/L18 预告） 会话 jsonl 钉死；画像分域记忆；全局留空
6安全边界 闸门、确认、对账、留痕 防御阶梯（A12）、fail-closed（A13）、证据链（A16） content_guard + dry-run + readback 对账

三、一条消息走完六件套（把前置课串成流水线）

你在 Easel 说"帮我写条小红书笔记"
 → [① Harness] gateway 收到，拼 system prompt，调 LLM        （A3 的循环启动）
     system = [②] SOUL 人格 + AGENTS 规则 + CONTEXT 路径      （A5 的稳定前缀）
 → [③] LLM 按 frontmatter 路由到技能 xhs-note-creator，       （A2 的路由）
     读该技能 SKILL.md（此刻才进上下文）                       （A5 的渐进披露）
 → [④] SKILL.md 让 LLM 写文案；字数校验、图片规格全调脚本      （L5 的"模型数不清字数"）
 → 产物写 outputs/<主题>/，[⑤] 本轮只绑当前画像的 memory.md   （A6 的作用域）
 → [⑥] 发布前 content_guard 扫描，默认 dry-run 等确认          （A12 阶梯 3/4 级）

六件套不是理论分类——是这条链上真实存在的六个站点。你已经在概念上走过一遍， 接下来整个正课就是在真实代码里再走一遍。

四、读 agent 仓库的六问（可迁移技能，正式版）

拿到任何 agent 项目按序六问，30 分钟定位构造： ① 循环在哪？找 harness 入口，看它监听什么、调哪个模型 API。
② 系统提示词由什么组成？找 SOUL/AGENTS 类文件，数常驻 token。
③ 能力怎么声明与路由？函数工具、MCP、还是技能目录？路由发生在模型侧还是代码侧？
④ 哪些事固化在脚本、哪些留给模型？可靠性的分水岭。
⑤ 状态和记忆存哪、作用域多大？全局记忆是红旗。
⑥ 边界在哪？有没有闸门、确认、对账——没有边界的 agent 不可交付。
